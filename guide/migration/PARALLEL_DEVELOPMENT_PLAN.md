# Stardis GPU迁移项目 - 并行开发计划 (4周紧凑版)

## 执行摘要

**调整策略**: 采纳用户建议，采用并行开发模式最大化效率
**核心思路**: 构建工程师与图形工程师并行工作，框架先行，算法后填
**时间目标**: 4周完成核心迁移 (原计划8周)

## 1. 并行工作流设计

### 1.1 双线并行策略
```
┌─────────────────────────────────────────────────────────────┐
│                   构建工程师 (Build Engineer)                │
│ 任务线A: Makefile → CMake转换 + Windows CPU构建            │
│                                                             │
│ 目标: 在Windows上构建可运行的CPU版本Stardis               │
│ 输出: 验证通过的CMake构建系统 + Windows可执行文件         │
└─────────────────────────────────────────────────────────────┘
                            │
                            │ 第2周末: CMake构建验证完成
                            │
┌─────────────────────────────────────────────────────────────┐
│                   图形工程师 (Graphics Engineer)             │
│ 任务线B: DX12开发环境 + 路径追踪框架搭建                  │
│                                                             │
│ 目标: 搭建命令行控制的DX12光线追踪/路径追踪软件框架       │
│ 输出: 可扩展的DX12渲染框架，等待算法填充                 │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                   第3周开始: 算法迁移和集成                 │
│ 将验证过的CPU算法迁移到DX12框架中                         │
│ 逐步替换框架中的占位实现                                 │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 并行工作优势
1. **时间压缩**: 原本串行的环境搭建和框架开发变为并行
2. **风险隔离**: 构建问题和框架问题相互独立，互不影响
3. **验证提前**: CPU版本在Windows上先验证，确保算法正确性
4. **框架就绪**: DX12框架提前完成，算法迁移直接填充

```cmake

├── src/CMakeLists.txt              # 主库源代码
├── tests/CMakeLists.txt            # 测试目标
└── cmake/                         # 自定义模块
    ├── FindRsys.cmake             # 第三方库查找
    ├── FindS2D.cmake

# 依赖处理策略
1. Windows优先: 使用vcpkg提供依赖
2. 功能等效: 寻找Windows上的等效库或重新实现
3. 配置兼容: 保持与Linux版本相同的配置选项
```
