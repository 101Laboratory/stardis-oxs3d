# Stardis GPU迁移项目 - Vibe Coding顺序方案

## 核心理念
**不绑定时点，只保证顺序** - 在vibe coding模式下，按正确顺序推进，自然完成

## 三大并行任务线

### 任务线A: 构建工程师 (CMake迁移)
```
顺序约束: A1 → A2 → A3 → A4 → A5
```

#### A1. 分析现有构建系统
- 解析Makefile和config.mk结构
- 识别所有编译目标和依赖关系
- 分析第三方库依赖 (rsys, s2d, s3d, senc2d, senc3d, ssp, swf)
- 理解平台特定编译选项

#### A2. 设计CMake架构
- 设计分层CMake结构 (库、可执行文件、测试)
- 规划依赖管理策略 (vcpkg vs 源码集成)
- 定义构建配置选项 (Debug/Release, 双精度开关)
- 设计Windows特定适配方案

#### A3. 实现CMake转换
- 转换主库构建规则 (libsdis)
- 转换测试目标构建规则
- 实现第三方依赖查找模块
- 添加安装和打包支持

#### A4. Windows构建验证
- 解决Linux特有API和头文件
- 处理平台编译选项差异
- 验证所有目标编译通过
- 运行基础测试验证功能

#### A5. 构建系统优化
- 添加增量构建优化
- 实现多配置支持
- 集成CI/CD流水线
- 文档化构建过程

### 任务线B: 图形工程师 (DX12框架)
```
顺序约束: B1 → B2 → B3 → B4 → B5
```

#### B1. DX12开发环境搭建
- 安装配置Visual Studio 2022 + Windows SDK
- 集成DirectX Agility SDK
- 配置vcpkg依赖 (directxmath, directx-headers等)
- 验证双精度支持 (RTX 4090)

#### B2. 基础DX12框架
- 创建设备和命令队列
- 实现资源管理框架 (缓冲区、纹理)
- 构建描述符堆管理系统
- 添加调试层和验证层支持

#### B3. 计算着色器框架
- 实现HLSL编译和加载管道
- 构建计算着色器管理
- 实现根签名和PSO缓存
- 添加着色器反射工具

#### B4. 路径追踪基础框架
- 设计场景数据结构 (几何、材质、相机)
- 实现光线生成和求交框架
- 构建蒙特卡洛采样系统
- 添加结果收集和显示

#### B5. 命令行控制框架
- 实现参数解析和配置管理
- 添加日志和进度报告系统
- 构建性能测量工具
- 实现错误处理和恢复

### 任务线C: 算法迁移 (依赖A和B完成)
```
顺序约束: (A完成 ∧ B完成) → C1 → C2 → C3 → C4 → C5
```

#### C1. 算法分析准备
- 分析CPU算法核心流程
- 映射数据结构到GPU格式
- 设计并行化策略
- 确定迁移优先级

#### C2. 基础功能迁移
- 数学库和工具函数迁移
- 几何处理和数据加载
- 随机数生成系统
- 基础验证框架

#### C3. 核心算法迁移
- 蒙特卡洛射线跟踪实现
- 热路径计算迁移
- 格林函数求解器
- 边界条件处理

#### C4. 集成和验证
- 算法集成到DX12框架
- GPU/CPU结果对比验证
- 精度和性能测试
- 边界情况测试

#### C5. 优化和完善
- 性能分析和优化
- 内存访问优化
- 稳定性改进
- 最终文档和示例

## 关键依赖关系

### 硬依赖 (必须顺序)
```
A1 → A2 → A3 → A4 → A5
B1 → B2 → B3 → B4 → B5
(A5完成 ∧ B5完成) → C1 → C2 → C3 → C4 → C5
```

### 软依赖 (建议顺序)
- A3进行时可以开始B2 (框架基础)
- A4验证时可以开始B3 (着色器框架)
- B4完成时A应该接近完成
- C2可以部分并行于C3 (基础与核心)

### 同步点
1. **设计同步**: A2完成后与B2设计接口
2. **接口定义**: A3/B3进行时定义数据交换格式
3. **集成准备**: A4/B4完成后准备C1分析
4. **最终集成**: C3完成后进行完整系统测试

## Vibe Coding工作流

### 每日节奏
```
早上: 检查进度，确定当日焦点
上午: 深度工作，解决关键技术问题
下午: 集成测试，代码审查，文档更新
晚上: 计划次日，记录问题和思路
```

### 周度节奏
```
周一: 新任务启动，技术方案确认
周二-周四: 核心开发，问题解决
周五: 集成测试，进度总结
周末: 弹性时间，创新探索
```

### 心态指导
- **不追赶时间**: 按正确顺序推进，质量优先
- **自然完成**: 每个任务做到位，下一个自然开启
- **保持流动**: 遇到阻塞时切换任务线
- **信任过程**: 正确顺序保证最终成功

## 技术风险应对

### 构建风险
- **依赖库Windows不可用**: 寻找替代或重新实现核心功能
- **编译选项复杂**: 分步骤迁移，先核心后优化
- **测试环境差异**: 保持最小测试集，逐步扩展

### 框架风险
- **DX12复杂性**: 从最小可行产品开始，逐步添加功能
- **双精度性能**: 实现混合精度回退策略
- **内存管理**: 严格资源生命周期管理

### 算法风险
- **精度损失**: 保持CPU参考实现，逐步骤验证
- **并行化困难**: 分析算法数据依赖，设计合适并行策略
- **性能不达标**: 分析瓶颈，针对性优化
