# STARDIS 毕业研究成果整理与 101Lab 发布方案

本目录用于把求解器、编辑器、论文源工程、开发文档和实验资料交接给 101Laboratory，供后续研究者阅读、复现和继续开发。盘点日期为 **2026-10-09（Asia/Shanghai）**。

按最终确定的组织原则，采用 **stardis-research 总入口，加 stardis-oxs3d、stardis-editor、stardis-thesis 三个子模块仓库**。主仓库统一保存 CPU 基线、GPU 实现与全部研究分支，文档、场景、实验脚本和数据索引与代码配套；worktree 不单独建库。论文仅公开完整 LaTeX 工程及必要资源，不发布整篇论文的生成 PDF、编译中间文件或本地环境。其他研究材料按用户要求完整纳入公开方案，包括评审、答辩记录和失败实验。

## 本次盘点的关键发现

- 三个工作区共计 **48,968 个文件、23.419 GiB**；不含 Git 对象、虚拟环境、部分缓存和本目录，包含构建产物及多工作树重复文件。此数值不是拟发布包大小。
- `D:/Stardis-GPU` 顶层没有 Git 仓库；`guide/`、`debug_issues/`、`optimization/`、主要实验数据因此没有随核心代码自动发布。
- 公开的 [stardis-cuda](https://github.com/EricSolshkov/stardis-cuda) 只有 `main`、`opt/merge-phase` 两个分支，均指向 `d89963a3f09d`；本地主仓库还包含一个未推送提交、其他实验分支和两个 stash。
- CPU Wavefront 消融实现、WoS 修复/验证、编辑器功能、论文正文/图表和模板均有本地未提交内容。现有远端快照不足以代表完整毕业成果。
- CPU 历史涉及 30 个嵌套仓库路径/commit 引用，其中 29 条引用的提交对象不在当前 CPU 父仓库中（27 个不同 SHA）；不能把现存父历史直接视为全部子仓库历史。
- 原始剖析目录约 **12.92 GiB**；单个 `gpu_trace.csv` 约 **3.72 GiB**，需要附件分包。小体积 CSV、脚本、结论应直接进入研究总库。
- 论文源工程候选集约 **14.35 MiB、126 个文件**，含必要插图；可去掉的整篇论文 PDF 为 **47.55 MiB**。候选集经过静态引用检查，尚未做干净环境编译验收。
