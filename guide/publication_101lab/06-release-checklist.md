## P5 针对性验收

1. **源码完整性**：在全新目录获取主仓库，CPU baseline 与 GPU 主线都可按 README 配置；构建日志重定向。
2. **最小运行**：各选一个小场景/小样本，分别保存 stdout 和 stderr。说明结果只覆盖该版本与配置。
3. **实验复现**：优先重画论文物理一致性图、核对单/双池和 pool scan 表，再验证后端基准。无需先重跑全量历史测试。
4. **编辑器**：针对当前 task runner 等修改运行相关测试，做一次场景读写与任务命令检查。
5. **论文**：在新导出的源工程编译，确认引用/插图/字体无缺失；只把源码提交。
6. **档案**：从拟发布包解包一次，核验文件数量、大小、SHA-256，验证大 CSV 的重组哈希。
7. **版本关联**：任一论文实验都能沿 `论文图表 → experiment_id → 代码 ref/补丁 → 输入 → 命令 → 输出 → 解析脚本` 查到资料；缺失项有明确标记。
8. **组织交接**：确认实际维护权限及至少一位后续维护者。仓库转移、Git push 和附件上传在整理结果可审阅后实施。
