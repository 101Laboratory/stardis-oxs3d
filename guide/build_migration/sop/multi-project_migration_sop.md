# LLM 精简迁移 SOP（LLM-First）

    适用对象：执行 Makefile → CMake + Windows/MSVC 迁移任务的 LLM
    优先级顺序即执行顺序，不得违反

## 0. 最高优先级：行为与安全约束（不可违反）

### 0.1 禁止假设（绝对规则）

- 不得做任何假设
- 不得补全缺失信息
- 不得基于经验推断意图
- 不得引入文档中未明确给出的规则或映射

### 0.2 异常即停止原则

当出现以下任一情况时：

- 输入文档未定义处理规则
- 存在多种可能映射但未明确指定
- 平台或构建语义无法确定等价关系
- 跨项目语义是否一致无法判定

**必须立即停止该部分迁移，并记录到异常文件**

异常文件要求：

- 文件名：migration_exception.md
- 内容必须包含：
  - 原始文本片段（原文）
  - 所属文件
  - 无法迁移的原因（客观描述）
  - 影响范围

### 0.3 审计优先原则（强制）

- 任何迁移行为之前，必须先完成审计
- LLM 的所有行为必须基于“当前已存在的审计产物”
- 审计未完成，不得修改构建或代码

## 1. 输入与依赖（必须确认）

在执行任务前，LLM 必须确认以下文件存在且可读：

### 1.1 单项目迁移依赖

- [make_2_cmake_migration_sop.md](./sop/make_2_cmake_migration_sop.md)  
- 原始 Makefile
- 原始 config.mk
- 项目源代码
- 测试集

### 1.2 多项目迁移额外依赖

- [dependency_graph.md](../dependency_graph.md)
- [cross_project_audit/](../cross_project_audit/)

若缺失任一项，**不得继续执行迁移。**

## 2. 审计阶段（必须先执行）

### 2.1 单项目审计（每个项目必须）

必须生成或更新以下文件：

- project_manifest.json
- public_api.json
- feature_flags.json
- platform_assumptions.json
- migration_exception.md

这些文件是 **后续迁移与跨项目同步的唯一事实来源。**

### 2.2 跨项目审计（如适用）

- 仅消费审计产物，不直接分析代码

- 仅在以下文件中记录结果：

  - cross_project_audit/summary.md
  - cross_project_audit/api_conflicts.md
  - cross_project_audit/feature_conflicts.md
  - cross_project_audit/platform_conflicts.md

## 3. 单项目迁移执行规则（严格顺序）

### 3.1 前置检查

在迁移项目 P 前，必须确认：

- P 的依赖项目已完成迁移（依据 dependency_graph.md）
- 当前跨项目审计是最新状态
- 未解决冲突已被明确标注

### 3.2 执行迁移

- 严格按照 make_2_cmake_migration_sop.md
- 只做文档中允许的映射
- 平台差异必须显式隔离
- 测试是唯一行为规格

### 3.3 迁移后审计（必须）

迁移完成后，必须：

- 重新执行本项目审计
- 更新所有审计产物
- 检查是否引入新的跨项目问题

## 4. 多项目迭代规则（如适用）

### 4.1 迭代模型

```
读取 dependency_graph
↓
读取 cross_project_audit
↓
选择下一个可迁移项目
↓
执行单项目迁移
↓
重新审计并更新审计文件
↓
回到下一项目
```

### 4.2 禁止事项

- 禁止并行迁移存在依赖关系的项目
- 禁止在单项目中隐式修复跨项目问题
- 禁止跨项目推断语义或依赖

## 5. 测试与验收（不可弱化）

- **不得修改测试期望**
- **不得删除测试以通过构建**
- **测试失败必须通过代码或平台适配修复**
- Windows 与 Linux 测试必须分别通过

## 6. LLM 允许与禁止的行为总结

### 6.1 允许

- 按文档执行规则
- 基于审计产物做判断
- 记录异常并停止

### 6.2 禁止

- 推断作者意图
- 合并不同项目语义
- 自动裁决冲突
- 隐式引入新规则

## 7. 终止条件

**LLM 必须停止执行**，当且仅当：

- 输入不完整
- 规则未定义
- 出现未裁决异常
- 审计状态不一致

## 8. 核心原则（必须内化）

**审计是事实，测试是规格，**
**文档是唯一规则来源，**
**停止比猜测更正确。**
