# ENC 查询消融实验设计

> 对应审查意见：第 4 章"补充 ENC 6-ray vs Jordan-Brouwer 的定量消融"  
> 与 §4.5 RT/CP 吞吐量实验对齐，继承相同硬件平台、场景生成与计时方法论。

---

## 1. 实验目标

定量对比两种 ENC 实现的 **查询级吞吐**，回答：

| 对比维度 | 指标 |
|---------|------|
| 吞吐量（MQuery/s） | 不同场景复杂度下的 ENC 查询峰值吞吐及稳态吞吐 |
| 等效射线消耗 | 单次 ENC 查询折合射线+CP 数 |
| GPU/CPU 加速比 | 与 Embree 6-ray baseline 的吞吐比 |
| 场景复杂度缩放 | 三角形数量从 1K→1M 时两种方案的衰减因子 |

## 2. 对比方案

### Baseline: 6-ray 投票法（CPU Embree / star-3d）

已有实现：`star-3d` 后端的 `enclosure_query()` 函数。

- 每次查询发射 6 条射线（±X, ±Y, ±Z）
- 对命中面法线投票，多数决确定 enc_id + side
- 退化时追加随机方向 fallback 射线

**等效消耗**：6 × RT 查询/ENC（退化时 7）

### Ours: CP + 单射线 Jordan-Brouwer 分解（GPU OptiX / oxstar-3d）

已有实现：`oxstar-3d` 后端的 `enclosure_query()` 函数。

- 第一步：1× CP batch（复用 `m_sbt_cp`）→ 得到 prim_id → enc_id
- 第二步：1× RT batch（复用 `m_sbt_rt`，+X 方向）→ 法线点积判定 side
- 退化旁路：d* < ε_degen 直接由 CP 结果出，跳过 RT

**等效消耗**：1 × CP + 1 × RT / ENC（退化时仅 1 × CP）

### 3.2 ENC 专有配置

#### 场景生成

与 CP 实验一致，使用 PCG 随机三角形网格，但需额外构造**封闭腔体结构**（ENC 查询的前提）：

| 参数 | 值 | 说明 |
|-----|-----|------|
| 场景复杂度 | 1K, 10K, 100K, 1M 三角形 | 与 CP 实验复杂度梯度一致 |
| 腔体构造 | 每个复杂度级别构造 1/2/4 个嵌套封闭多面体 | 测试多腔体投票正确性场景 |
| 腔体形状 | 封闭 convex hull（由随机点集的凸包生成） | 保证 Jordan-Brouwer 条件精确成立 |
| 查询点分布 | 均匀分布在场景 AABB 内 | 含腔体内部(~30%)、腔体外部(~60%)、近界面退化(~10%) |

> **关键**：CP 实验中场景无需封闭性约束（只需三角形汤），但 ENC 实验场景必须包含语义正确的封闭腔体——否则 enc_id 无定义。因此需要额外的场景构造步骤，但三角形数量级与 BVH 深度保持一致。

#### 批次规模

| 批次规模（查询数） | 说明 |
|------------------|------|
| 4,096 | 低负载基线 |
| 65,536 | CP 稳定区起点 |
| 262,144 | 中等负载 |
| 1,048,576 | 典型 Wavefront pool 对应量级 |
| 8,388,608 | RT 饱和宽度 W_sat |

## 5. 预期结论结构

根据已有 RT/CP 数据推算预期量级：

1. **GPU ENC 吞吐** 的瓶颈应在 CP 步骤（CP 吞吐 ~11.72 MQ/s 远低于 RT 5.15 GRays/s），因此 ENC 吞吐量应略低于纯 CP 吞吐（因额外一次 RT launch 的 overhead）。
   - 预估 GPU ENC: ~8–11 MQ/s (10K 三角形)
   
2. **CPU 6-ray 吞吐** = CPU RT 单线程吞吐 / 6。CPU 单线程 RT ~0.83 MRays/s (10K 三角形)，则 6-ray ENC ~0.14 MQ/s。
   - 预估 GPU/CPU 单线程: ~60–80×
   - 预估 GPU/CPU 16T: ~3–5×（CPU 16T RT ~15.45 MRays/s → 6-ray ENC ~2.58 MQ/s）

3. **场景复杂度缩放**：GPU 侧衰减因子预计与 CP 接近（BVH 深度主导），CPU 侧衰减因子预计更陡峭（6× 放大 L3 cache 压力）。

4. **等效射线消耗**降低 67%（6→2），但因 CP 单次代价高于 RT（SM 执行 vs RT Core），实际吞吐提升幅度会低于 3×。消融的核心论点不是"我们比 6-ray 快 N 倍"，而是"我们用更少的查询次数+GPU 并行化获得了等效正确性，同时释放了 4 条冗余射线的带宽"。

## 6. 实验步骤摘要

```
Step 1: 场景构造
  - 对每个复杂度级别 (1K/10K/100K/1M)，生成包含 4 个嵌套凸包腔体的随机网格
  - 预生成查询点集 (每批次规模一组, PCG seed=77)
  - 标注每个查询点的 ground truth enc_id (通过高精度几何判定离线预计算)

Step 2: GPU 方案 (oxstar-3d) 测量
  - 对每个 (复杂度, 批次规模) 组合:
    - cudaEventRecord 分别包裹 CP launch 与 RT launch
    - 记录 CP kernel time, RT kernel time, 总 ENC 时间
    - 验证输出 enc_id 与 ground truth 一致 (正确性校验)
  - 5 次取中位数

Step 3: CPU 方案 (star-3d) 测量
  - 对每个 (复杂度, 批次规模) 组合:
    - 调用 star-3d 的 enclosure_query(), 单线程+16线程
    - 计时取中位数
    - 验证输出一致

Step 4: 汇总
  - 填充 ENC-1, ENC-2, ENC-3 三张表
  - 绘制吞吐-批次规模曲线 (与 RT/CP 同风格)
  - 写入 §4.5 新增小节
```
