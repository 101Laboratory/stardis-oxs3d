## 7. 逻辑与内容审查

### 7.1 核心贡献评价

**贡献一：Wavefront FSM 求解器（第三章）** — 最强贡献

技术深度突出。从递归求解器的 19 个挂起点分析出发，推导确定性状态机设计约束，最终构建包含 59 个细粒度状态的完整 FSM。路径状态持久化设计（AoS 布局、冷热字段分离、联合体局部变量）体现了工程成熟度。实验验证极为严谨——13 个测试场景覆盖全部物理过程组合，282 个数据点通过 $3\sigma$ 检验，逐像素 Z 检验经 Bonferroni/BH 双重校正后报告零显著差异。

性能分析同样扎实：$T_A/T_B = 6.5\times$ 时间分解精确定位 CPU Cache 瓶颈，路径池容量扫描（8k→16k 出现 $2.25\times$ 退化）和查询后端消融实验定量证明架构解耦的有效性。

**贡献二：OptiX GPU 查询后端（第四章）** — 方法贡献明确

RT 查询映射虽为平凡操作，但 CP 查询的 AABB 代理 + 零长度射线重构方案和 ENC 查询的 Jordan-Brouwer 拓扑分解方案具有方法新颖性，且提供了完备性/正确性的严格论证。统一后端架构（单 Pipeline、5 SBT、双 GAS）设计简洁合理。

RT 查询实测 5.15 GRays/s（RTX 4090）vs CPU Embree 16 线程约 333× 加速比；CP 查询在 10K 三角形场景下约 19.7×，1M 场景下达 45.9×。

**贡献三：GUI 编辑器（第五章）** — 工程贡献

StardisEditor 作为配套工程工具完成度高，DSL 解析/写出闭环、三维可视化、画笔标注、任务队列等功能模块设计合理。Cornell Box 案例展示了完整工作流。该章定位为工程贡献而非学术贡献，论述深度得当。

### 7.2 逻辑链条完整性

第二章理论基础→第三章求解器→第四章后端→第五章工具的递进逻辑清晰：
- §2.2.6 分析递归框架的四个障碍 → §2.3 引入 Wavefront 范式 → 第三章实现
- §2.4.5 定义三类查询需求 → §3.2 枚举 19 个挂起点 → §3.3.3 定义后端接口 → 第四章实现
- §3.3.3 建立 CPU-GPU 混合架构 → §4.4 统一查询后端 → §5.4.5 任务配置串联前两章

### 7.3 潜在弱点

1. **单场景性能评估**：端到端性能仅在 porous 场景上评估。虽然该场景覆盖全部物理过程，但不同几何复杂度和物理配置下的加速比趋势未充分展开（§3.4.3.6 仅做了初步趋势分析）。
2. **加速比尚有限**：8-16 线程下 $1.3\times$-$1.4\times$ 加速，32 线程仅 $1.02\times$。论文已坦诚分析 CPU Cache 瓶颈为根因，但审稿人可能质疑实用价值。建议在讨论中更强调"瓶颈定位"和"全 GPU 架构路线图"的学术价值。
3. **CP/ENC 查询无独立伪代码**：第四章 RT 查询虽为平凡映射但在第二章已有伪代码（算法 1-4），而 CP 和 ENC 查询作为方法贡献仅以散文描述，缺乏结构化算法呈现。
