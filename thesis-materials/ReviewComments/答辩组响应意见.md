## 一、专家肯定的工作

两位专家在以下方面给出了一致的肯定，作者将在答辩陈述中重点呈现：

1. **核心方法层面**：将递归求解器等价改造为持久化状态机的 Wavefront 求解算法，将耦合热输运蒙特卡洛框架适配到批量化执行范式，构成本文最具学术价值的贡献。
2. **GPU 映射层面**：针对 RT/CP/ENC 三类异构几何查询提出的 OptiX 统一加速管线，特别是 CP（自定义 AABB 代理 + 零长射线）与 ENC（Jordan–Brouwer 分解）的映射方案具有实质性创新。
3. **工程闭环层面**：DSL 驱动的 GUI 编辑器形成了从场景建模到批量仿真的完整工具链。
4. **写作与态度层面**：结构严谨、实验设计周密，对递归求解器结构性障碍的剖析与物理一致性验证体现了科学严谨的研究态度。

## 三、逐条回应

### C1 — CPU 调度瓶颈与全 GPU 架构（P1-1、P2-4）

**作者态度**：完全接受。本轮以文字补强为主，不补新实验。

**已有支撑（不依赖新实验）**：
- 第三章 §3.4.3 路径池容量对比（8 192 → 16 384，2.25× 退化）+ $T_A/T_B$ 时间分解（GPU 设备侧仅 10.9%、加速比上界 1.12×）已**主动、定量**地暴露 CPU 末级缓存是当前主导约束；
- 查询后端消融实验（WF + Embree 单池 = 426 s，相对 Baseline 4.0× 退化）从另一个维度交叉确认了 GPU 后端的必要性。

**修改落实（纯文字）**：对第六章 6.2 节"（一）全 GPU 求解器架构"作三项更正与重写：
1. **删除以 CPU 缓存为目标的措辞**：全 GPU 路线下 L1/L2 / LLC 不再是优化目标，原稿涉及该方向的论述全部移除；
2. **PicardN 递归栈定位修正**：该栈在 GPU 端已从 \texttt{path\_state} 分离为独立 SoA 数组 \texttt{sfn\_arr[]}，并非未来工作；进一步的"PENDING Pool 完全外化"（消除 \texttt{sfn\_arr} 整列）作为已有设计草案的明确后续方向写入；
3. **核心难点深化**：把 GPU 端 Wavefront 调度内核的实现作为本节重点深入讨论——包括持久线程执行模型、状态推进与 OptiX 内联光追的 single-kernel 融合、warp 级 stream compaction 的路径同质化、\texttt{path\_state} 热区的进一步 SoA 化。架构成果可复用性（FSM、字段冷热分组、查询 ABI）作为收尾段。修改详见同目录文件《[论文修改方案.md](论文修改方案.md)》§3.1。

**答辩陈述要点**：CPU 实例化的目的是在受控环境下验证 Wavefront 等价改造的正确性与查询后端的吞吐上限；FSM 状态机定义、\texttt{path\_state} 字段、批量提交/回填接口协议在架构层面与执行设备无关，可被全 GPU 方案直接复用。当前混合架构精确定位了 CPU 端性能天花板，为后续全 GPU 演进提供了实验依据，而非系统性能的终点。

### C2 — 测试场景规模与几何多样性（P1-2、P2-2）

**作者态度**：部分接受。受客观条件限制，本轮不补新场景性能测试，改以"既有数据显性化 + 定性趋势讨论 + 后续工作展望"三步回应。

**澄清说明（基于既有数据，可立即写入论文）**：
- 物理一致性验证实际**已使用 13 个递进复杂度验证场景、共 282 个有效数据点**全部通过 3σ 检验，论文当前版叙述未对此充分突出；
- 端到端统计等价性检验、性能评估与消融实验集中在 porous（约 13K 三角形），原因是该场景**在单一案例中同时激活辐射–传导–对流三类物理过程**，便于在固定工程边界下进行严格受控对比；
- 第四章已分别给出 RT (5.15 GRays/s)、CP (19.7\~45.9× 加速)、ENC（两次 \texttt{optixLaunch} 上界）三类查询的独立基准，可从查询层面对其他几何/腔体拓扑下的查询规模进行**定性**推断。

**修改落实（纯文字）**：
1. 在第三章 §3.4 开头补入 13 场景测试体系一览表（A2/A3/A7/B3/B5/C3/D1/D2/E3/E5/F1/F2/I1），逐项说明每个测试的物理场景、解析参考解类型与主要验证功能，使既有 282 数据点的覆盖广度显性化；该表基于项目内一致性分析报告整理，不引入任何新实验；
2. 在 §3.4.3 末追加"几何特征敏感性讨论"段，基于 $T_A/T_B$ 模型 + BVH 渐近行为 + 三类查询基准，**定性**预期薄壁高密度结构、多嵌套腔体、超大规模场景下的性能趋势；措辞严格使用"定性预期/趋势"，不冒充实测，**且不**在第三章末提及多 GPU 协作（GPU 在混合架构下并非瓶颈，越级展望应避免）；
3. 重写第六章 6.2 节"（二）"：**删除多 GPU 与 NVLink 互联展望**（GPU 非当前瓶颈、纯 GPU 尚未实现，跨卡互联属越级），改为"借鉴现代高性能路径追踪的工程优化技术"——按 (a) Wavefront 分阶段调度、(b) Coherent Shading 路径排序、(c) SoA + packed 数据布局、(d) 内联光追与 SER、(e) Russian Roulette 五条务实方向组织；
4. 第六章总结段末追加"系统化的几何敏感性与超大规模场景扩展性验证留待后续工作"一句。

详见《论文修改方案.md》§3.2。

**答辩陈述要点**：13 场景物理一致性 + 282 数据点 3σ 通过已确认架构正确性；porous 在性能评估上的代表性来自其同时激活三类物理过程的工程意义；针对几何多样性的系统化性能复测已识别为明确的后续工作方向。

### C3 — 物理模型简化假设的边界与扩展（P1-3、P2-3）

**作者态度**：完全接受。本类修改为纯文字补强，不涉及新实验。

**当前简化的位置**：表面采用漫射灰体假设、流体被视为透明非参与介质、对流换热使用恒定/线性化系数。这些假设在工业红外仿真常用场景下成立，但论文未集中讨论其适用边界以及失效情形下的扩展路径。

**修改落实（纯文字）**：
1. 在第二章"小结"之前新增"建模假设与适用边界"小段，集中陈述三条工程简化及其物理含义；
2. 在第六章 6.2 节"（三）更丰富的物理模型"段按"假设失效场景 $\to$ 学术挑战 $\to$ 工程扩展"三段式重写，**先学术后工程**：
   - **参与性介质**：学术上需在路径密度中引入沿光程的指数衰减项与散射相函数，重新论证 Woodcock null-collision、NEE 等方差缩减技术下蒙特卡洛估计器的无偏性，以及 PicardN 在非线性辐射边界与体积参与项耦合下的收敛性；工程上扩展 FSM 与 RT 查询管线（约 5\~7 个状态、新增体积步进查询）；
   - **多光谱辐射**：学术上需在路径空间引入波长维度，重新建立路径概率密度归一与无偏性条件（Spectral Importance Sampling 或 Hero Wavelength），并推导 $\varepsilon(\lambda,T)$ 与 Planck 函数 $B_\lambda(T)$ 在 PicardN 内展开的一致性；工程上扩展 \texttt{path\_state} 波段字段与材质表，FSM 与查询管线不变；
   - **强非线性对流系数**：学术上需将 $h_{cv}(T)$ 与辐射项 $h_{rd}(T)$ 在 PicardN 框架内同等处理，重新推导多温度采样的乘积估计形式，并以 majorant 上界或额外方差缩减手段保证估计器方差可控；工程上 advance 阶段引入温度依赖闭包，FSM 不变；
3. 在第六章 6.2 节"（四）"将原稿"交互式预览与编辑器增强"重写为"**仿真管线与工业/DCC 软件数据互通**"——在超大规模工业场景下，编辑管线本身成为新瓶颈，务实方向是与 CAD/CAE（CATIA/SolidWorks/ANSYS via STEP/CGNS）、DCC（Blender/Maya via USD/glTF）、仿真工作流引擎（ParaView/Cassiopée）的数据互通，以及 BNF 文法的结构化标准化（JSON Schema / USD Schema）；交互式降噪预览作为附属增强保留。

详见《论文修改方案.md》§3.3。
